# Windows 与安卓共享剪贴板

共享通过自己部署的 ntfy 中转服务连接手机与电脑，可在不同网络下使用。普通打字不依赖中转服务。共享默认关闭；「自动发送新复制」是另一个独立开关。

Windows 端由方寸桌面伴侣负责连接，需保持伴侣进程运行；关闭设置窗口不等于退出进程。支持 Windows 10/11，密钥保护依赖当前 Windows 账户。

## 第一次配对

1. Windows 打开方寸设置的「剪贴板历史 → 跨设备共享 → 连接与配对设置」。安卓打开「我的 → 剪贴板共享」。两端使用同一 HTTPS 服务地址和话题。默认值为 `https://clip.kivohub.site`、`fangcun-clipboard`，实际以自己的部署为准。
2. 选择一端生成共享密钥，再「复制配对资料」。在另一端手动粘贴到配对资料输入框并导入；不需要在两端各生成一把密钥。配对资料以 `fangcun-clip-v1:` 开头，包含共享密钥，只交给自己的设备。
3. 每台设备分别填写自己的中转服务 Token 和设备名称。配对资料不含 Token；导入资料不能代替服务器授权。服务器须给每个设备的 Token 授予该话题的读写权限。
4. 保存连接设置。生成或导入密钥、保存连接设置后，共享保持关闭，需要在两端手动开启。安卓可先点击「测试连接」；Windows 开启后根据状态栏确认授权及连接结果。
5. 先手动发送一条普通测试文字，检查另一端的「共享」列表是否出现来源设备名和时间。确认两个方向均可用后，再按需单独开启「自动发送新复制」。

安卓显示密码键盘时会暂停共享。填写完令牌或密钥后，先收起键盘，再测试连接或复制配对资料。

Windows 的 Token 和密钥输入框不会回填已保存内容，只显示是否已加密保存；密钥标识不是密钥。留空只保留当前服务器已有的 Token。更换服务器必须重新填写该服务器的设备 Token，旧 Token 不会发往新地址。连接资料有未保存改动时，先保存，再开启共享或发送。

## 发送与接收

| 操作 | Windows | 安卓 |
| --- | --- | --- |
| 查看本机内容 | 「本机历史」或 `Alt+V` 的「本机」页 | 键盘剪贴板的「本机」页 |
| 查看远端内容 | 「跨设备共享」或 `Alt+V` 的「共享」页，显示来源和时间 | 键盘剪贴板的「共享」页，显示来源和时间 |
| 使用收到的文字 | 点击条目复制，再在目标输入框按 `Ctrl+V` | 点击条目，明确上屏到当前普通输入框 |
| 手动发送本机文字 | 「发送当前剪贴板」，或本机条目的发送按钮 | 本机条目长按菜单中的「发送到共享」 |
| 自动发送 | 另外开启「自动发送新复制」，只处理之后的新复制 | 同左；仅 App 或键盘可见且隐私边界允许时工作 |

收到文字只进入共享收件箱，不会自动覆盖系统剪贴板或写入输入框。Windows 点选后只复制，不会模拟粘贴或发送聊天消息。`Alt+V` 的本机与共享列表分别查看、搜索；新内容到达不会替用户切换分类。

启动伴侣、显示窗口、刷新列表、启用共享或恢复监听，都不会扫描上传旧剪贴板历史。暂停 Windows 的「本机监听」也会暂停自动发送；共享接收与手动发送仍由共享开关控制。退出伴侣进程后不再连接。

## 隐私与本机存储

- 每设备使用独立的服务 Token；两端使用同一把随机生成的 32 字节共享密钥。正文、设备名和时间在客户端使用 AES-256-GCM 加密后分片上传。中转仍能看到连接、话题、传输时间和密文大小。
- Windows 使用 DPAPI CurrentUser 保护共享凭证及共享状态，不回退到明文密钥文件。更换 Windows 账户或无法解密时需要重新配置，不能直接复制受保护文件到其他账户使用。
- Windows 尊重 `ExcludeClipboardContentFromMonitorProcessing`、`CanUploadToCloudClipboard=0`、`CanIncludeInClipboardHistory=0` 等排除标记。配对资料和明确复制的远端内容带排除标记，不录入本机历史，也不作为新的本机复制回传。
- 安卓沿用无痕、密码框、禁止个性化学习及敏感剪贴板门禁；退出私密输入后不会追补期间复制的内容。共享消息不会绕过当前输入会话校验。
- 重置共享配置只处理共享连接与共享收件箱，保留原本机剪贴板历史。普通本机历史仍沿用原有存储方式，不能将共享状态的 DPAPI 保护理解成所有历史均已加密。

## 断线、失败与范围

支持纯文本，每条最多 **32 KiB UTF-8**，精确保留换行、空格和 emoji；超限明确报错，不静默截断。消息最长有效期为 **24 小时**，复制时会再次检查有效期，过期内容不能使用。能否找回离线消息也取决于中转的缓存时长及恢复上限；界面出现同步缺口时，不代表内容已全部补齐。

**Windows 待发队列仅在内存中，不跨进程重启恢复。** 发送过程中退出伴侣、关闭共享、修改连接或耗尽重试，未完成内容需要重新手动发送。以界面成功状态和另一端实际收到为准；「已加入发送队列」不等于已送达。不要把本机仍保留的原文字当成会自动重发的承诺。

遇到错误时：

- **401/403、授权失败**：检查本设备的 Token、服务地址与话题读写权限；修正保存后重新开启。不要关闭服务器鉴权来排查。
- **无法读取 Windows 受保护资料**：在当前 Windows 账户重新配置；重置共享不会删除本机历史。
- **已保存但没有内容**：确认两端都已开启共享、密钥标识对应同一份配对资料，先手动发送新测试文字。自动发送不会追补开启前的内容。
- **文字已在共享列表但没有进入应用**：Windows 点击复制后，仍需回到目标输入框按 `Ctrl+V`。

## 共同协议与验收

两端使用 [共同协议 v1](https://github.com/ZhaoHaiBln/FangCunIME/blob/codex/clipboard-sharing/android/docs/clipboard-sharing/PROTOCOL-v1.txt) 和[公开测试向量](https://github.com/ZhaoHaiBln/FangCunIME/blob/codex/clipboard-sharing/android/docs/clipboard-sharing/vectors-v1.json)。测试向量中的密钥仅用于验证，不用于实际配对。安卓使用说明见 [手机与电脑共享剪贴板](https://github.com/ZhaoHaiBln/FangCunIME/blob/codex/clipboard-sharing/android/docs/clipboard-sharing/README.md)。

本地协议、存储和页面检查不等于真实设备跨网验收。使用自己的设备 Token，分别验证电脑到手机、手机到电脑，随后检查关闭共享、断线恢复、伴侣重启和显式复制后的防回流行为。

本文档的共同协议链接指向正式合仓的工作分支；此公开构建分支仅将文档相对链接改为完整地址，编译源码与正式工程一致。
