# Windows 0.6.5 界面细化

以0.6.4为基准，先查看实际伴侣前端与原生候选绘制，再参考 [GoodUI](https://goodui.dev/) 的设置分组、材质和稳定按压反馈。保留木框活字、经典打字机、绿屏终端、极客机械的素材、明暗配色、候选硬件造型及流光；不增加尚未实现的AI语音功能。

## 改动

- 设置卡片统一轻微左上高光，明确键盘焦点和按压反馈，外部按钮位置保持不变。最小窗口下标题、预览选项可换行，内容区域独立滚动。
- 切换皮肤只修改皮肤，保留“跟随系统／浅色／深色”的选择。保存以本机回执为准，连续编辑依次合并；失败保留已确认值并明确提示，“完成”等待保存结束。首次读取失败时不能把默认值覆盖到用户配置。
- 剪贴板主体使用原生复制按钮，置顶、删除、发送各自独立；支持Tab、Enter和空格，重绘保留可用焦点。操作失败不模拟成功，不删除可见历史，也不关闭浮窗。共享的加密、配对、路由及后端命令不变。
- 候选编码在宽度不足时省略前段、保留新输入的尾段；完整组合串、候选内容及窗口预算不变。显示结果在布局更新时缓存，流光绘制不重复测量。备用原生设置的小字按底色选择可读前景，版本从CMake统一读取。

## 本机复验

前端继续使用原有依赖，从 `windows/app/` 运行 `npm run build` 或 `npm run dev`。另装Python Playwright及Chromium后，可从 `windows/` 运行：

```sh
python3 tests/ui_regression.py --base-url http://127.0.0.1:5173/ --output ./ui-regression-report
```

回归启动真实TypeScript页面并注入确定的Tauri IPC假数据，仅允许本机地址；不访问账号、真实剪贴板或中转服务。覆盖四皮肤明暗、模式保留、连续保存、迟到事件、失败反馈、复制与动作分离、键盘操作、窄窗、浮窗、稳定按压及关闭动画。

原生纯规则断言保留在 `tests/test_keyhandler.cpp`，包括长编码、窄槽、UTF-16、比例字宽、测量次数及四皮肤明暗文字对比；完整Windows编译和核心测试沿用现有CMake/CTest路线。

浏览器截图来自Linux Chromium的实际前端预览；原生显示规则的本机测试不等于Windows DirectWrite、WebView2、COM注册或宿主输入法实测。实际构建、源指纹、安装身份及下载验证结果记录在下一节。

## 本轮核验与交付

本机TypeScript检查和Vite生产构建通过；C++20的KeyHandler、编码显示和配色规则断言通过。前端完整19项最终通过，0失败、错误、跳过；首轮新脚本的选择器同时匹配body与button、旧删除按钮名称和未等待入场动画造成12项fixture失败，保留首轮源码/日志/XML，仅修正定位与等动画结束，再完整重跑，未放宽按压位置或业务断言。95个产品输入在两轮前后逐字一致，96个最终输入包含新增回归脚本。实际前端截图已目视检查；本地证据在 `/workspace/ci-artifacts/fangcun-windows-goodui-0.6.5/`。

保存队列保护同一窗口的连续编辑及迟到通知，不声称解决所有进程同时全量写同一INI的冲突。剪贴板前端以既有IPC回执为准；原生监听命令现有的偏好写盘错误未透传，本轮不重写该后端协议，也不把运行中监听状态等同磁盘持久化证明。

Windows完整编译、安装包和直链仍待下一步实际核验，不把浏览器预览或源码审查当作Windows实机验收。
